    Évaluation¶

    Tests unitaires et fonctionnels réalisés¶

    Nous avons structuré les tests autour de trois suites principales (unittest), en isolant les dépendances externes par mock lorsque nécessaire, et en validant les réponses via FastAPI TestClient côté API.

    Recommandation (recommendation.py)¶

    • test_recommend_course_combinations_basic : simulation de load_courses() et IntentProcessor.match_courses_by_interest() pour forcer un corpus connu, puis vérification que recommend_course_combinations() retourne une liste de groupes (liste de listes) cohérente pour un semestre donné et une liste de cours déjà complétés.
    • test_map_semester_to_term : validation du mapping 1 → autumn, 2 → winter, 3 → summer, 4 → autumn.
    • test_generate_course_combinations : à partir d’un petit échantillon, vérification que les combinaisons générées respectent k=2 et que le nombre de groupes n’excède pas max_groups.

    NLP (nlp.py)¶

    • test_detect_intent : vérifie que IntentProcessor.detect_intent() retourne bien une chaîne décrivant l’intention.
    • test_match_program_name : contrôle que match_program_name() renvoie une liste de programmes candidats.
    • test_extract_interest_from_courses : accepte None ou une chaîne, selon que l’intérêt puisse être extrait à partir des titres/descriptions.
    • test_match_courses_by_interest : valide que la fonction renvoie une liste (top-k) de cours ordonnés par similarité sémantique.

    API de chat (chat.py)¶

    • Initialisation : montage d’une application FastAPI avec inclusion du routeur via app.include_router(chat.router, prefix=/api/v1), puis utilisation de TestClient.
    • test_empty_message_returns_400 : un message vide doit produire un HTTP 400.
    • test_salutation_intent : en forçant detect_intent="salutation", une salutation est attendue dans la réponse 200.
    • test_recommend_courses_asks_program : avec detect_intent="recommend_courses", l’API doit demander le programme de l’utilisateur.
    • test_unknown_intent_triggers_clarification : pour une intention inconnue, l’API renvoie un message de clarification et incrémente le compteur d’ambiguïtés.
    • test_clarification_exceeds_limit_resets_state : si clarification_count > 3, l’état est réinitialisé et l’API propose de recommencer.

    Isolation par mocks
    Les appels coûteux ou externes sont simulés pour garantir des tests déterministes et rapides :
    src.services.recommendation.load_courses, src.services.nlp.IntentProcessor.match_courses_by_interest, ainsi que côté API get_state, increment_clarification, reset_state, log_intent_sequence et intent_processor.detect_intent.

    Résultats et couverture des tests¶

    L’exécution complète de la suite de tests unitaires et fonctionnels a été réalisée avec succès, en utilisant unittest et FastAPI TestClient :

    • Nombre total de tests : 20
    • Succès : 20 / 20 (100 %), aucun échec ni erreur.
    • Durée totale d’exécution : ≈ 32 secondes

    Couverture de code (coverage.py) : - Modules recommendation.py et nlp.py : 92 %
    - Module chat.py : 88 %
    - Module state.py : 85 %
    - Couverture globale du projet : 89 %

    Ces résultats montrent que l’ensemble des fonctionnalités critiques du chatbot (recommandation, NLP, gestion d’état et API) sont largement couvertes par les tests, garantissant un haut niveau de fiabilité.

    Évaluation de performance¶

    Les tests ont été effectués sur un MacBook Air avec Intel Core i5 1.6 GHz et 8 GB RAM.

    • Chargement initial du modèle (IntentProcessor) : 1.67 sec
    • Temps de réponse API /chat : 4.95 sec

    Détection d’intention (BERT) : - Salutation initiale : Temps 0.82 sec, Mémoire 331.17 MB - Demande sans précision : Temps 0.08–0.10 sec, Mémoire 0.82 MB - Identification du programme seul : Temps 0.07–0.08 sec, Mémoire 0.05 MB - Expression d’un intérêt sans programme : Temps 0.08 sec, Mémoire 3.07 MB

    Correspondance sémantique (intérêt seulement) — Complexité de l’intérêt : - Simple : Temps 43.92 sec, Mémoire 636.91 MB - Modéré : Temps 41.06 sec, Mémoire 335.38 MB - Complexe : Temps 35.37 sec, Mémoire 339.44 MB

    Recommandation de cours (intérêt) : - Intérêt simple : Temps 38.65 sec, Mémoire 613.90 MB - Intérêt modéré : Temps 39.18 sec, Mémoire 321.02 MB - Intérêt complexe : Temps 145.85 sec, Mémoire 730.04 MB

    Occupation disque : - Modèle BERT local : 418 MB - Cache Transformers : 1.6 GB

    Évaluation d’utilisabilité¶

    Évaluation heuristique selon Nielsen (Nielsen & Molich, 1990) : 1. Visibilité du statut du système : le chatbot affiche immédiatement des messages après chaque action. 2. Correspondance avec le monde réel : les termes employés (programme, cours, trimestre) sont familiers aux étudiants. 3. Contrôle et liberté de l'utilisateur : possibilité de corriger ses réponses ou réinitialiser le dialogue. 4. Cohérence et normes : interface suivant les conventions usuelles (chat, boutons, navigation par semestre). 5. Prévention des erreurs : boutons-guides limitant les fautes de saisie. 6. Reconnaissance plutôt que mémorisation : choix d’options visibles, sans devoir mémoriser des noms précis. 7. Flexibilité et efficacité d’utilisation : saisie libre en langage naturel ou sélection rapide. 8. Design esthétique et minimaliste : mise en page sobre et fonctionnelle, centrée sur le dialogue. 9. Aide au diagnostic et à la résolution d’erreurs : reformulations ou redémarrage proposés en cas d’échec. 10. Aide et documentation : aide contextuelle intégrée aux messages, sans manuel externe.

    Comparaison avec les objectifs initiaux¶

    • Recommandation sémantique par domaine : objectif partiellement atteint via BERT, mais absence de catégories explicites limitant la précision.
    • Filtrage par préalables : identification correcte des cours non accessibles, mais pas encore de remplacement automatique.
    • Reconnaissance d’intention multilingue : remplacement des solutions initiales (spaCy, Rasa, fuzzy) par BERT, plus performant.
    • Planification interactive : affichage des recommandations dans les blocs semestre, mais glisser-déposer vers calendrier encore à finaliser.
    • Performance du modèle : taille réduite des données limitant la généralisation, mais performances suffisantes pour le cadre du projet.
